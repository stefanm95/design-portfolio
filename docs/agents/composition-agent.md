# Composition Agent Rules

Composition is the heart of the presentation system.

Composition controls:

- pacing
- density
- breathing
- asymmetry
- cinematic tension
- rhythm
- environmental spacing

---

## Composition Philosophy

The system intentionally avoids:

- normalized layout systems
- utility-only composition
- CMS-style spacing systems
- generic responsive templates

Composition should remain:

```txt
authored
```

NOT:

```txt
algorithmically homogenized
```

---

## Composition Ownership

Composition belongs primarily to:

```txt
presentation/
```

supported by:

```txt
design/
```

Runtime may influence:

- density
- rhythm
- transitions
- atmosphere intensity

BUT runtime must NOT own:

- authored composition
- cinematic framing
- layout artistry
- presentation pacing structure

---

## Density System

Density influences:

- spatial breathing
- compositional pressure
- cinematic openness
- pacing perception

Density should eventually affect:

- section spacing
- reveal pacing
- stagger rhythm
- atmospheric restraint

NOT only container classes.

---

## Rhythm System

Rhythm coordinates:

- reveal cadence
- transition pacing
- cinematic timing
- experiential flow

Rhythm is:

```txt
behavioral orchestration
```

NOT:

```txt
animation decoration
```

---

## Important Rules

Avoid:

- universal spacing abstractions
- rigid grid normalization
- presentation homogenization
- algorithmic cinematic composition
- generic block-builder systems

---

## Composition Goal

Composition should evolve toward:

```txt
runtime-aware cinematic orchestration
```

while preserving:

- authored intentionality
- narrative pacing
- experiential asymmetry
- cinematic breathing

# Composition System

## System Identity

The composition system is architected as:

### runtime-influenced cinematic composition

Composition exists to orchestrate:

- experiential pacing
- cinematic spacing
- compositional hierarchy
- reveal grouping
- atmospheric breathing
- environmental continuity

The composition system is:

### authored

NOT:

### dynamically generated

---

## Core Composition Philosophy

Composition should feel:

- cinematic
- restrained
- intentional
- breathable
- experientially cohesive

Composition should evolve from:

```txt
manually tuned spacing
```

into:

```txt
runtime-influenced cinematic pacing
```

WITHOUT losing:

### authored restraint

---

## Runtime Composition Flow

The intended composition orchestration flow is:

```txt
profile
→ composition contract
→ cadence resolution
→ scene modulation
→ composition reactivity
→ presentation behavior
→ rendered composition
```

Composition should:

### consume orchestration

NOT:

### generate orchestration

---

## Composition Responsibilities

The composition system is responsible for:

- section assembly
- cinematic spacing
- reveal grouping
- experiential pacing
- compositional hierarchy
- visual breathing
- environmental continuity

Composition should coordinate:

- runtime orchestration
- cadence
- scene modulation
- experiential density

WITHOUT:

- adaptive layout systems
- dynamic render trees
- generated composition systems

---

## Composition Contracts

Composition contracts define:

- density
- rhythm
- pacing
- spacing pressure
- cinematic softness
- experiential structure

Composition contracts should remain:

### declarative

NOT:

### behavioral engines

---

## Composition Reactivity

Composition should subtly react to:

- cadence softness
- scene modulation
- cinematic pressure
- atmospheric intensity
- experiential density

Examples:

### immersive + spacious

Should feel:

- deeper
- slower
- more breathable
- more cinematic

through:

- expanded spacing
- increased breathing
- softer reveal grouping
- deeper pacing

---

### editorial + tight

Should feel:

- sharper
- cleaner
- restrained

through:

- compressed spacing
- tighter grouping
- cleaner cadence
- reduced breathing

---

## Runtime Influence Rules

The runtime should:

### influence composition

NOT:

### control composition

Meaning:

- subtle modulation
- restrained pacing shifts
- cinematic spacing influence
- compositional breathing

NOT:

- dynamic layout generation
- runtime-authored structure
- adaptive composition systems
- orchestration-driven UI generation

❌ Scene-specific layout systems  
❌ Behavioral composition graphs  
❌ Composition state machines

✅ Compositional restraint

## Composition Reactivity Layer

Composition reactivity should remain:

### lightweight and compositional

It should:

- subtly influence spacing
- subtly influence breathing
- subtly influence reveal grouping

It should NOT:

- become orchestration infrastructure
- become runtime state management
- become adaptive rendering logic

---

## Presentation Relationship

Presentation consumes:

- composition contracts
- composition pacing
- cinematic spacing
- experiential grouping

Presentation should NOT:

- own composition orchestration
- duplicate composition semantics
- dynamically restructure composition

---

## Semantic Constraint

Every composition semantic MUST:

### produce meaningful experiential consequence

If a composition abstraction:

- does not improve pacing
- does not improve cinematic feeling
- does not improve experiential cohesion

REMOVE IT.

Avoid:

### composition inflation

---

The strongest quality of the composition system is:

### restrained cinematic pacing

Composition should feel:

- intentional
- authored
- breathable
- cohesive
- runtime-aware

WITHOUT becoming:

- adaptive
